この資料は、あなたが sekimori を「やる」と決めるための 1 枚です。専門知識は前提にしません。上から順に、用語を 4 つ、何が困っているか、sekimori が何をするか、判断の要点と読めるように並べています。図の色は 3 色だけです。緑が sekimori の足す物、金が「別々の記録を結ぶ糸（link）」、朱が「今、情報が落ちている場所」です。

用語は 4 つ一枚で言うと今の姿sekimori を入れるとspan の木4 つの仕事証明する引っ越しさせる診る関所の通行表手形の探し方言わないこと予定判断の要点用語集

00 · 読む前に用語は 4 つだけ覚えれば足ります

この分野の言葉は難しく聞こえますが、中身は宅配の追跡と同じです。1 つの注文（リクエスト）が、いくつかの Lambda（小さなプログラム）を順に通って処理されます。その旅を記録する仕組みが「トレース」です。

01 · 一枚で言うとtrace context という通行手形を、関所ごとに持たせて通す

ひとつのリクエストは、Lambda を出た後に EventBridge（イベントの配送係）と SQS（順番待ちの列）を通り、別の Lambda に届きます。境界を越えるごとに「どのリクエストの続きか」を示す手形が要ります。sekimori は、この手形を境界の形に合わせて書き（inject ＝ 差し込む）、受け取る側で読み取ります（extract ＝ 取り出す）。

02 · 今の姿ADOT layer だけでも「link」は繋がる。落ちる場所が 3 つ残る

先に正直に書きます。AWS が配る ADOT layer を Lambda に付けると、Lambda が AWS を呼ぶたびに X-Ray 形式の手形が自動で付きます。EventBridge も SQS もそれを運ぶので、受け側の Lambda の記録（invocation span ＝ 1 回の実行を表す span）には link が付きます。ここまでは layer の仕事で、sekimori の手柄ではありません。

  • 「SQS で trace を繋ぐのは初」とは言いません。OpenTelemetry contrib が長年やっています。
  • EventBridge の detail に context を入れる発想は Datadog が先です。ただし vendor 固有の形です。
  • sekimori が名乗るのは「vendor 中立で W3C 標準の手形」と「record ごとの span」です。

03 · sekimori を入れると手形を 2 枚書き、record ごとに span を開く

送る側（producer）は injectEventBridgeEntry(entry) の 1 行です。EventBridge 用の X-Ray 形式の手形 TraceHeader と、event の中身に残る業界標準の手形 traceparent を同時に書きます。受ける側（consumer）は withSqsRecord(record, fn) です。record（届いた 1 件）ごとに span を開き、送った側の span へ link を張ります。

  • 層（layer）の仕事は奪いません。X-Ray の header は layer が付けたまま、W3C の手形を足すだけです。
  • 失敗した record の span は ERROR で閉じ、例外はそのまま投げます。ReportBatchItemFailures と両立します。
  • FIFO の 1 record 処理では parent: "producer" で親子にもできます。

04 · span の木1 本の invocation span が、record の数だけ枝を持つ

06 · 証明するprobe：「繋がっているはず」を、実 AWS で確かめる

observability の設定は、誰かが SDK client を差し替えた瞬間に静かに壊れます。probe は壊れたことに気づくための恒久経路です。

  • 近い OSS は ServerlessSpy ですが、あれは「event が届いたか」を見ます。probe は「trace が繋がったか」を見ます。
  • report は成果物です。README の飾りではなく、docs/evidence/ に日付付きで残します（CI artifact 化は repo 公開後に整備予定）。

07 · 引っ越しさせるmigrate：X-Ray SDK の書き方を OpenTelemetry API に変える

X-Ray SDK は 2026 年 2 月から maintenance mode です。新機能は入りません。AWS は ADOT か OpenTelemetry を勧めています。ただし終了日は公表されていません。だから慌てずに、しかし確実に引っ越す道具が要ります。

  • Powertools は Logger・Metrics・Idempotency・Batch を残し、Tracer だけを置き換えます。
  • Powertools 公式の OpenTelemetry Tracer は RFC のまま止まっています。出たら、その実装への移行路に位置づけ直します。
  • GitHub と npm を探した範囲で、この用途の codemod は存在しません。

08 · 診るdoctor：deploy 前に、観測の準備が揃っているかを 1 枚にする

  • AWS の MCP server は Transaction Search の有効化確認だけを持ちます。layer の版や env、IAM、索引 %、bundle まで束ねた物はありません。
  • Datadog の datadog-ci は Datadog layer 専用で、設定を書き換えます。doctor は中立で、読むだけです。

11 · 言わないこと「初」を名乗らない。どこが空いているかだけを言う

既にあるもの（sekimori は名乗らない）

  • SQS の trace 伝播。OpenTelemetry contrib が inject・extract・link を持ちます。
  • SNS Publish の inject。同じく contrib にあります。
  • AWSTraceHeader から span link を作ること。instrumentation-aws-lambda がやります。
  • EventBridge の detail に context を入れる発想。Datadog が _datadog で先にやりました。
  • Transaction Search の有効化確認。AWS の MCP server が持ちます。
  • EventBridge / SQS の CDK テストハーネス。ServerlessSpy があります。

空いているもの（sekimori が埋める）

  • vendor 中立で W3C 標準の EventBridge の手形（TraceHeader との二重書き）。
  • record ごとの CONSUMER span。部分バッチ失敗と両立する形で。
  • SNS envelope の読み取り、Kinesis と Step Functions の inject。
  • trace の連結を実 AWS で証明する probe と、その report（CI への組み込みは repo 公開後の予定）。該当 OSS なし。
  • X-Ray SDK / Powertools Tracer からの codemod。該当 OSS なし。
  • 準備状況を 1 枚にする中立の doctor。

upstream に取り込まれたら、sekimori 側の実装は削って upstream を指します。契約テストの形を contrib の ServiceExtension に合わせているのは、そのためです。吸収は失敗ではなく、計画どおりです。

14 · 用語集本文に出た言葉を、一言ずつ

用語一言で
trace / spantrace は 1 リクエストの旅の記録。span はその 1 区間。span が集まって trace になる
trace context / traceparent「この処理はどのリクエストの続きか」を示す手形。traceparent はその業界標準（W3C）の書き方
link別々の trace を「同じ客だ」と結ぶ糸。親子ではない
OpenTelemetry（OTel）trace や metrics の取り方の業界標準。特定ベンダーに依存しない
ADOT layerAWS が配る Lambda 用の部品。付けるだけで OTel の計装（記録の仕組み）が入る
X-Ray / X-Ray SDKAWS の trace サービスと、その古い書き方のライブラリ。SDK は 2026 年 2 月から新機能なし（終了日は未公表）
Transaction SearchCloudWatch の機能。全部の span を保存し、後から検索できる
PowertoolsAWS 公式の Lambda 用ユーティリティ集。その Tracer は X-Ray SDK 依存
ESM（Event Source Mapping）SQS などから Lambda に message をまとめて渡す仕組み。1 回の件数は batch size の設定次第（SQS Standard は最大 10,000 件、FIFO は最大 10 件）
invocation spanLambda の 1 回の実行を表す span。ADOT layer が自動で作る
inject / extract手形を message に差し込む／message から取り出す
codemodソースコードを機械的に書き換える道具。ここでは X-Ray SDK の書き方を OTel の書き方に変える
upstream / contrib本家のプロジェクト。contrib は OpenTelemetry の AWS 向け実装が集まる場所
probe探針。常に動かしておく小さな経路で、trace が繋がっているかを毎回確かめる
